# Architecture

```
apps/web  --(axios, Bearer access token + httpOnly refresh cookie)-->  apps/api  --> MongoDB
        \_______________ packages/shared (roles, permissions, progress rules) _______________/
```

- **API layout:** `src/modules/<domain>/*.routes.ts` (auth, users, academic, syllabus, plans, teaching, progress, assessments, reports, notifications/audit), `src/models`, `src/middleware` (auth, validation, errors, CSRF guard), `src/scripts` (bootstrap admin, backup).
- **Validation:** Zod on every body/query. Errors are `{error:{code,message,details?}}`. Lists return `{data, meta:{page,pageSize,total}}`.
- **Auth:** short-lived access JWT; refresh token in an httpOnly cookie, rotated on every use with reuse detection. `/auth/refresh` and `/auth/logout` require the `X-Requested-With: ssms` header.
- **Authorization:** role -> permission map stored in DB (editable by Super Admin) and enforced by `authorize(...)` on the server; the UI only hides what the server would reject. Teachers are additionally restricted to their own section/subject assignments.
- **Progress:** computed on demand by one function (`computeUnits`) per section x subject x chapter. Weighted activities (Teaching 40, Notebook work 15, Notebook correction 15, Worksheet 10, Test 10, Revision 10 by default; editable, must total 100). Non-applicable activities are excluded and weights re-normalised. A chapter is *completed* only when its completion record is APPROVED; daily topic entries never complete a chapter.
- **Web:** route guard by permission, forced password change redirect, UI kit in `components/ui` (hand-written shadcn-style components, not generated by the shadcn CLI).
